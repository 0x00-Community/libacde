# 说明文档怎么写

说明分给 Agent 和给人两部分，改说明或新增说明时都按这个来。

- **`AGENTS.md`**：只放硬规则（代码约定、格式化、提交与推送）和路由，路由指向 `docs/agents.md` 或 `docs/agents/` 里的具体一篇。架构、模块、机制、构建发版步骤写在 `docs/agents/`。
- **`docs/agents/`**：权威版本。契约、接口、不变量、命令、目录、测试与排查步骤都写在这里，改代码时同一个提交里改。每篇一个主题、能单独读懂；先写结论，再写理由；一条超过三行就拆开。
- **`docs/agents.md`**：`docs/agents/` 的目录，每篇一行“什么时候读（动词开头，具体到任务）”。新增、改名、合并文档时同步改这里。
- **`docs/humans/`**：写给第一次接触本仓的人：是什么、怎么理解整体、为什么这样设计、怎么上手。细节不重复写，链接到 `docs/agents/` 对应的那篇。每篇开头一行 `与 docs/agents 同步于 <日期>`。
- **`docs/humans.md`**：`docs/humans/` 的目录，每篇一行简介和建议的阅读顺序；仓库根的 `README.md` 指向它。
- **一个意思只写一处**：要在别处提到时写指向，不复制内容；挪动或合并文档时把所有指向它的链接（文档、代码、脚本）一起改掉。
- **只写现状**：被取代的做法、某次测试的经过、批次和轮次编号不写进来，经过留在提交记录里。
